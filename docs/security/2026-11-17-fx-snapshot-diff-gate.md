# Synthetic FX ledger snapshot diff gate

This is a **bounded and dependency-free verifier**, not a release approval or a migration. It compares synthetic old/new ledger JSON snapshots with **exact integer cents**, fails for any native-balance mutation or unexplained ref-currency delta, and prints a machine-readable FX_SYNTHETIC_DIFF report. No PostgreSQL/Redis/network calls occur. This is one building block for [release blocker #45](https://github.com/man612/Kasana/issues/45).

Run on a disposable/synthetic fixture only:

    node scripts/finance-fx-snapshot-diff.mjs before.json after.json expectations.json

Snapshot format: schemaVersion 1; fixtureId beginning with synthetic-; distinct revision strings; rows with a unique stable key, kind (transaction/account/balance/loan/investment), nativeCents and refCents decimal integer **strings**. Manifest format: fixtureId and refChanges array, each containing key, beforeRefCents, afterRefCents and a specific reason. Inputs are capped at 2 MiB; max 10,000 rows; cents are checked within signed bigint range. Comparisons use JavaScript BigInt, not binary floating point. The CI's lightweight Node preflight runs seven positive/negative unit tests.

**Limitations:** The test fixture values are illustrative arithmetic and were not generated by running two different app versions. The tool cannot know whether a claimed reason for change is valid and must be paired with an independent finance oracle and stable synthetic scenario IDs. Completing issue #45 requires producing two real independent, identical-fixture disposable DB snapshots (old-head/new-head) covering transfers, loans, investment, splits, and backdated transactions, plus a restore rehearsal and explicit historical accounting policy. Do not feed personal financial exports into this tool or use the test results to authorize deployment.
