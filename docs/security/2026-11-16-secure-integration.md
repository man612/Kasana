## Installation security contract

Installed patch-package **8.0.1** source (`dist/index.js`) and its [upstream README](https://github.com/ds300/patch-package#usage) confirm that `--exclude` filters **patch creation**, not application. Local patch application also defaults to exit zero on failure. The earlier report's claim that frontend-only selection/failure handling worked is superseded by this correction.

- `post-install.sh` explicitly stages patch files into a disposable directory only when query-string is absent. It skips exactly the backend's query-string patch and applies all other patches with **`--error-on-fail`**, including outside CI. No blanket ignore or install fallback hides patch errors.
- The dependency-free runtime gate resolves query-string through Polygon, checks the **installed** decoder version and exercises percent decoding, malformed input and query serialization under Node 24. It is invoked by postinstall, backend build/dev/prod commands, explicit backend Docker install steps and the production entrypoint **before migrations**. The production-image CI smoke invokes it with networking disabled and without starting the application or migrations.
- Every Docker install path copies the gate before npm ci. Frontend-only installs still apply the existing UI patches. CI cache keys include locks, patches, the hook and the gate; exact cache hits reapply patches and require the backend runtime check. Docker COPY layers likewise invalidate on these inputs. Cached dependency directories must not be treated as trusted merely because a lock hash matches.
- **Supported runtime installation:** pinned Node 24.22.1 and `npm ci` with lifecycle scripts enabled. `npm ci --ignore-scripts`, `npm_config_ignore_scripts=true`, omitted patch tooling/dev dependencies, and direct starts that bypass the entrypoint/gates are **unsupported** runtime installation modes. npm itself permits explicitly disabling lifecycle scripts; this repository cannot make that flag run its own hook. Restore a complete supported install with `npm ci`, then run `node scripts/check-provider-runtime.cjs`. Do not interpret lockfile contents as proof that the bridge was applied.
- The preview workflow's scripts-disabled installation and the dev frontend's install-on-failure fallback were removed. A fresh backend offline build without dependencies fails its gate instead of producing a usable-looking unpatched image. No deployment or real data-bearing dependency volume was changed.

Six subprocess regressions exercise clean/repeated patching, missing frontend-only dependency, local UI/backend conflicts, unpatched/stale dependencies and a required missing backend. They use the actual installed patch-package CLI, synthetic packages and the real decoder. Clean root and frontend-only npm ci passed. A second real root install with `--ignore-scripts` succeeded at npm level but **failed the explicit runtime gate** with `decodeComponent is not a function`; explicit patch application then restored the gate. This proves the unsupported-mode failure, not general safety of skipping other packages' lifecycle hooks.

Lajur.'s internet-facing backend uses **Express**, including its OAuth/MCP route; it does not import Hono, its Node adapter, serveStatic, mount, csrf or form validator. MCP authentication checks the OAuth bearer token and finance scopes before transport dispatch. Yahoo's separate bundled MCP server is not exposed. The installed Hono code is removed from the affected range nonetheless; future Hono exposure must receive route-specific review. Tests exercise wildcard authorization, encoded line terminators and a real loopback Node-adapter server.

Fast-uri is used for AJV schema references through the MCP SDK, not for Lajur. redirect/URL allowlists. The SDK client can validate externally supplied schemas/metadata, while Lajur. publishes its own server tool schemas; an attacker-controlled URI-normalization path was not established here. Authentication alone is not a blanket safety argument. Tests reject encoded dangerous schemes while preserving local JSON-schema references, required properties and numeric types. The IPv6 regression rejects the vendor's long-percent/newline payload and retains normal IPv6 parsing. Express parses incoming queries with qs; no application comma-array stringify use was found, but hostile serialization is now tested against the patched dependency. No request behavior or authentication boundary was relaxed.
