# Audit 13 temuan mobile Lajur.

Basis pengerjaan adalah `ff481765d` dari branch `lajur-mobile-audit-pr64`, yaitu revisi aplikasi yang dirujuk cabang operasi terbaru yang tersedia. ## Cache, startup, dan keamanan data

- IndexedDB `budget-tracker/query-cache` tetap dipakai. Daftar cache mencakup mata uang, kategori, grup akun, kurs, tanggal transaksi paling awal, serta daftar akun, portofolio, pinjaman, langganan, koneksi bank dan payee. Cache keuangan yang dipulihkan dijadwalkan untuk konfirmasi di latar. Snapshot kosong sengaja tidak dipulihkan. Tabel mata uang ISO dapat menggunakan cache tanpa request konfirmasi.
- Persistensi dibatasi 24 jam, terkait versi build, dan dibersihkan melalui alur logout dan pergantian pemilik cache. Transaksi lengkap, grafik saldo, notifikasi, dan data sinkronisasi tetap melalui API. Pemeriksaan sesi, profil, mata uang dasar serta status operasi pemulihan, perubahan mata uang dasar, dan penghapusan batch tetap diperlukan sebelum halaman keuangan dibuka.
- Service worker menangani aset dengan nama berbasis hash dan fallback navigasi offline. Nginx memvalidasi dokumen, metadata versi, runtime config dan service worker sesuai kebijakannya masing-masing. API privat merespons `Cache-Control: private, no-store`. Akses offline saat memulai aplikasi menampilkan halaman offline, agar sesi dan saldo tidak dianggap terverifikasi.
- Reactivity Dashboard mempertahankan layout widget untuk akun yang sama dan menggunakan query per kebutuhan widget. Tata letak yang sudah ada tetap dipakai selama pengambilan preferensi. Indikator penyegaran dan error dirender tanpa mengganti saldo yang masih tersedia dengan skeleton.
- Pengukuran startup mengamati enam kelompok request utama. Sesi dan profil; pengaturan pengguna; mata uang dan kategori; probe operasi kritis; data Dashboard; serta notifikasi, SSE, onboarding dan banner keamanan. Dua periode pada grafik dan kategori adalah perbandingan yang diminta oleh widget. Startup yang diukur perlu dipisahkan dari refetch navigasi atau invalidasi setelah mutasi.

## Menjalankan ulang profil

Jalankan API sintetis lokal dengan pendaftaran dan onboarding uji. Sajikan build Vite produksi pada origin loopback, menggunakan konfigurasi Nginx produksi dan proxy `/api` ke backend sintetis. Gunakan build dari commit dasar dan build revisi pada port yang sama secara bergantian.

```bash
LAJUR_PROFILE_ORIGIN=http://localhost:8851 \
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium \
node packages/frontend/scripts/profile-startup.mjs sebelum > sebelum.jsonl
```

Skrip membuat akun sekali per run, mengisi satu akun IDR dan tujuh transaksi, membuka Dashboard dengan emulasi Pixel 7, dan mengumpulkan Network, Paint, Layout, dan heap melalui Chromium DevTools Protocol. Skenario warm memakai cache browser dan IndexedDB dari run yang sama. Jaringan lambat disimulasikan dengan latensi 160 ms, unduh 200.000 B/s dan unggah 75.000 B/s.

## Hasil pengukuran startup

Chromium 156, emulasi Pixel 7, API PostgreSQL dan Redis sintetis, Nginx produksi lokal, serta telemetri tanpa konfigurasi di kedua build. Waktu berasal dari dua run pada mesin bersama dengan variasi beban yang terlihat antar-reload. Pengurangan jumlah request dan byte aset dapat diperiksa langsung. Waktu render adalah observasi lab, sehingga persentase peningkatannya belum mewakili perangkat produksi.

| Skenario                                  | Saat grafik muncul, sebelum → sesudah | Request API, sebelum → sesudah | Request aset, sebelum → sesudah |
| ----------------------------------------- | ------------------------------------: | -----------------------------: | ------------------------------: |
| Cache kosong                              |                      17,41 → 5,81 dtk |                        27 → 27 |                       359 → 284 |
| Reload cache hangat, rata-rata dua reload |                      20,93 → 4,35 dtk |                        24 → 24 |                       359 → 284 |
| Hard refresh                              |                      10,25 → 3,72 dtk |                        24 → 24 |                       359 → 284 |
| Kembali dari Transaksi ke Dashboard       |                       3,94 → 1,50 dtk |                        10 → 11 |                           0 → 0 |
| Tutup dan buka kembali browser            |                      11,29 → 4,41 dtk |                        25 → 24 |                       393 → 284 |
| Reload hangat dengan jaringan lambat      |                       6,72 → 2,21 dtk |                        24 → 24 |                       359 → 284 |
| Offline                                   |       Fallback offline di kedua build |                          0 → 0 |                           0 → 0 |
| Status sesi API 503                       |  Kembali ke alur masuk di kedua build |                          1 → 3 |                         39 → 40 |

Pada cache kosong, first contentful paint terukur 1,50 → 0,88 dtk dan largest contentful paint 17,54 → 5,89 dtk. Pengukuran layout shift 0,064 → 0,092 dan heap Chromium 20 → 21 MB. Pada dua reload hangat, heap terukur 18 dan 27 MB sebelum perubahan, serta 19 dan 27 MB sesudah perubahan. Pengukuran browser mencatat layout dan tugas panjang. Profil ini belum mengukur jumlah render per komponen Vue. Pengulangan mengonfirmasi 284 permintaan aset dan 1.186.975 byte pada cold start. Satu hard refresh pengulangan memakan 106,6 dtk ketika lingkungan uji tersendat. File hasil mentah menyertakan sampel itu.

- Transfer aset yang dilihat CDP pada kunjungan pertama turun dari 1.417.190 menjadi 1.186.695 byte, sekitar **16%**. Dua chunk SDK opsional menghilang dari startup saat konfigurasi telemetri kosong.
- Dua reload hangat dijalankan di bawah service worker. Permintaan aset tetap muncul di panel Network dengan transfer nol. Cache Storage memegang 193 entri termasuk fallback offline. Pada cold start, IndexedDB berisi tujuh query yang memenuhi syarat. Reload hangat berikutnya tidak mengulangi request kategori dan daftar mata uang ISO.
- Pada perangkat uji, 24 GET/stream startup hangat termasuk pemeriksaan sesi, profil, preferensi, kunci operasi, perbandingan antarperiode, transaksi terkini, langganan dan notifikasi. Tidak ditemukan URL GET identik pada dua cold/warm startup yang dibandingkan. Navigasi ulang masih memuat query halaman tujuan. Snapshot grafik dan transaksi tetap melalui API.
- Dua request gabungan saldo di API sintetis teramati sekitar 187–231 ms pada sampel terakhir. Pemeriksaan sumber menunjukkan kueri gabungan untuk set akun dan rangkaian paralel untuk komponen saldo. `EXPLAIN (ANALYZE, BUFFERS)` atas join rentang akun/saldo mengambil 0,263 ms dari buffer hangat dalam fixture kecil. Redis melaporkan penggunaan 1,79 MB saat diamati. Sampel ini belum menunjukkan dasar untuk mengubah indeks atau jalur agregasi. Penggunaan CPU/RAM VPS dan performa data produksi belum diukur.
- Chromium menginstal PWA dan dua kali membuka Dashboard yang terautentikasi di jendela standalone dengan service worker aktif. Saat profil browser dipakai oleh akun sintetis kedua pada build yang sama, cache akun pertama hilang dan cache akun kedua dipulihkan. Pergantian build lokal dari `audit13-verified` ke `audit13-checked` menampilkan tombol Muat Ulang. Setelah tombol digunakan, Dashboard dan grafik tampil kembali, service worker aktif, dan IndexedDB menulis snapshot dengan versi baru. Hasil ini belum mencakup pemasangan pada perangkat Samsung, keyboard sistem Android, kondisi aplikasi kembali dari latar belakang, atau pergantian build pada VPS.

## Verifikasi hasil

Tujuh skenario utama Chromium lulus pada build produksi `audit13-final`. Lima skenario tambahan lulus untuk navigasi detail, validasi pinjaman baru, baca dan sunting pembayaran pinjaman, serta layout kendaraan untuk pemilik dan pengguna dengan akses baca pada 320 px dengan teks normal dan dua kali lipat. Pemeriksaan TypeScript frontend lulus dengan heap Node 6 GiB. Vite masih melaporkan chunk besar dan siklus dependensi, termasuk antara chunk ikon dan runtime Vue. Bootstrap dan navigasi yang tercakup di pengujian berhasil. Lint frontend dan validasi identitas, tautan dokumentasi, batas konfigurasi Compose, serta whitespace juga lulus. Pada uji unit terakhir terdapat 102 kasus terarah yang lulus jika digabung dengan pengulangan terisolasi tiga kasus editor. Pengulangan diperlukan setelah satu kasus melebihi batas lima detik ketika build dan browser berjalan bersamaan.

Pengujian ini mencakup Chromium dengan viewport mobile dan PWA Chromium standalone. Cakupan tersisa meliputi perangkat Samsung Browser Beta, pengukuran frame pacing pada perangkat fisik, keyboard virtual, scroll Dashboard untuk semua ukuran grup, serta seluruh kombinasi transaksi, lampiran, dan kondisi gagal jaringan. Status tunggakan pinjaman tetap membutuhkan data kejadian tagihan dan pembayaran aktual.
